Anatomie d'une backdoor

Premier exploit du lab : du scan réseau jusqu'à un shell root. Le fichier le plus simple pour comprendre la chaîne complète — reconnaissance, recherche d'exploit, exploitation, post-exploitation.

Chronologie

Six étapes concrètes : on scanne, on choisit un port, on cherche un exploit, on charge le module, on lance l'attaque, on vérifie l'identité obtenue.

Méthode exacte, en un coup d'œil

1
Reconnaissancenmap -sV -sC
Lister tous les services ouverts avec leurs versions exactes — sans préjuger du port à cibler.
2
Choix du portreconnaissance visuelle
Repérer, dans la liste, le service qui sort de l'ordinaire : version ancienne, ou accès non authentifié.
3
Recherche d'exploitsearchsploit
Croiser la version exacte du service avec la base d'exploits publics.
4
Sélection du modulemsfconsole / search / use
Charger précisément le module qui correspond à la version vue.
5
Configurationset RHOSTS / set LHOST
Donner au module la cible et l'adresse de retour du reverse shell.
6
Exploitation et vérificationexploit / getuid / whoami
Lancer l'attaque, vérifier l'identité obtenue, basculer en shell système.

-sVdétecte la version exacte de chaque service. Indispensable : une faille cible une version précise, jamais un service en général. -sClance les scripts NSE par défaut — bannières, options d'authentification, remarques utiles. triageFace à cette liste, on cherche ce qui sort de l'ordinaire : une version très ancienne, un service qui ne devrait pas être exposé, une mention anonymous login allowed.
