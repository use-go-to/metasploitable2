3

Connexion directe — netcat

Pas de module, pas d'exploit : une simple connexion TCP brute suffit.

kali@kali
$ nc 192.168.56.20 1524
root@metasploitable:/# whoami
root
ncnetcat ouvre une connexion TCP brute. Aucune négociation de protocole, aucun handshake applicatif. résultatLe service renvoie un prompt shell direct, sans mot de passe ni session préalable. La connexion elle-même est l'exploit. telnettelnet 192.168.56.20 1524 fonctionne aussi — netcat est simplement plus direct.

Ce qu'il faut vraiment comprendre

Une backdoor n'est pas toujours une archive piégée

Le cours #1 montrait une archive modifiée après compromission de la chaîne de distribution. Ici, c'est plus simple : le service a été délibérément configuré pour écouter sur un port et renvoyer un shell. Aucun code malveillant caché — juste un service qui n'aurait jamais dû être exposé.

Reconnaissance : l'anomalie plutôt que la vulnérabilité

Un scanner liste des dizaines de ports. Tous ne sont pas des failles. Certains — comme ingreslock sur ce port — sont des anomalies de configuration. Le travail du pentester est de repérer ce qui sort de l'ordinaire.

Shell direct vs shell reverse

Le cours #1 utilisait un reverse shell : la cible rappelait l'attaquant. Ici, c'est un shell direct : la cible écoute passivement et n'importe qui s'y connecte obtient un prompt. Pas de gestion de LHOST, pas de payload à envoyer.

Anatomie de la backdoor

Pourquoi un service peut se retrouver à exposer un shell root sans qu'aucun code malveillant n'ait été injecté.

Un service lancé en root

Sur Metasploitable 2, le port 1524 est associé à un démon démarré avec les privilèges root. Ce n'est pas une faille du démon lui-même — c'est son mode de déploiement qui est dangereux.

Le port 1524/tcp

Officiellement réservé à ingreslock, un service de verrouillage pour la base de données Ingres. Sur cette machine, aucun SGBD Ingres n'est installé — le port a été réutilisé pour autre chose. C'est cette incohérence qui doit déclencher l'investigation.

Ce qu'il n'y a pas à faire

Aucun exploit à chercher, aucun module à charger, aucun payload à configurer. La connexion netcat est l'exploit. C'est volontairement l'un des cours les plus simples du lab.

Détection & remédiation

Le point de vue du défenseur.

netstat -tulpn / ss -tulpnlister tous les ports en écoute et le processus associé — détecte immédiatement qu'un démon non reconnu écoute sur 1524
lsof -i :1524identifier quel processus a ouvert le port 1524 et sous quel compte
règle IDS (Snort/Suricata)détecter une connexion entrante sur 1524/tcp — aucun trafic légitime ne devrait y transiter
moindre privilègene jamais lancer un service avec les droits root s'il n'en a pas strictement besoin

Terminal d'entraînement

Rejoue la chaîne complète : lire la sortie nmap, repérer le port suspect, s'y connecter, vérifier l'identité obtenue, puis explorer librement.
